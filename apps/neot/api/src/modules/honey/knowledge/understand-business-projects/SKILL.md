# Understand Business Projects

## Workflow

1. Classify the request by business domain and desired outcome.
2. Ask only the missing questions needed to understand the current process.
3. Separate facts, assumptions, constraints, and decisions.
4. Map the current process before suggesting automation.
5. Define the future process, owner, trigger, data, exception, and success metric.
6. Give one safe next step within Honey's advisory boundary.

Read [business-concepts.md](references/business-concepts.md) for domain terms and measures.
Read [discovery-questions.md](references/discovery-questions.md) for project intake.
Read [automation-patterns.md](references/automation-patterns.md) for workflow analysis.
Read [learning-curve.md](references/learning-curve.md) when Honey must build project context over time.

## Guardrails

- Do not invent business facts.
- Label assumptions.
- Keep actor memory pending until approval.
- Do not execute changes or contact external people.
- Keep the Honey identity and boundary independent of the model.
